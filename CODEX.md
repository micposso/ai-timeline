# Codex Project Instructions

## Source of truth

- Read `AGENTS.md` before making changes. Its Next.js instructions are generated by the project and take precedence.
- Preserve existing user changes and keep edits focused on the requested task.
- Before changing Next.js code or APIs, consult the relevant guide in `node_modules/next/dist/docs/`.

## Project overview

This repository is a small design-system and portfolio site for Mira Studio.

- Framework: Next.js 16.3.8 with the App Router
- Language: TypeScript
- UI: React 19 and Tailwind CSS 4
- Components: `components/`
- App routes and global styles: `app/`
- Static assets: `public/`
- Storybook stories: colocated `*.stories.tsx` files and `stories/`
- Deployment: static export configured in `next.config.ts`

## Development conventions

- Prefer existing components and design tokens over introducing one-off markup or styles.
- Keep the visual language consistent: warm paper backgrounds, coral accents, navy contact section, rounded surfaces, and responsive layouts.
- Use semantic HTML, accessible names, keyboard-visible focus states, and meaningful image alt text.
- Keep client-side JavaScript to a minimum. Add `"use client"` only when interactivity or browser APIs require it.
- Use the existing `@/*` import alias for internal imports.
- Keep project data and page composition in `app/page.tsx`; keep reusable presentation logic in `components/`.
- Update or add a colocated Storybook story when changing a reusable component.
- Do not add dependencies unless the task requires them.

## Commands

```bash
npm run dev
npm run lint
npm run build
npm run storybook
npm run build-storybook
```

Run the narrowest relevant checks after edits; run `npm run lint` and `npm run build` for changes that affect application code or configuration.

## Important configuration

- `output: "export"` means the app must remain compatible with static export.
- Images are intentionally `unoptimized` for static hosting.
- `basePath` is `/nexjs-design-responsive-nyit2026`; preserve it unless deployment requirements change.
- `trailingSlash: true` is intentional.

## Completion checklist

- Confirm the requested behavior or content is implemented.
- Check responsive behavior when changing layout or styles.
- Preserve accessibility and existing visual direction.
- Run relevant validation commands and report any limitation or failure.
